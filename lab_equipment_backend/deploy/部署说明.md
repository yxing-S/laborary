# 后端部署说明（Linux + MySQL 8 + Nginx）

## 一、部署架构

```
浏览器
  └─ http://62.234.128.72:6664           前端静态文件（已有）
       ├─ /                -> /www/wwwroot/homework/dist
       └─ /real-api/...    -> http://127.0.0.1:8000/api/v1/...
                                后端 Django + Gunicorn
                                数据库 MySQL lab_equipment
```

前端已部署好的 Nginx 配置无需改动（`location /real-api/` 已按上述规则转发）。

## 二、服务器要求

- Python 3.10 及以上
- MySQL 8（本机 127.0.0.1:3306）
- 已安装 Nginx（前端站点正在使用）
- 后端端口 `8000` 未被占用

## 三、上传与一键部署

1. 将 `lab_equipment_backend_deploy.zip` 上传到服务器并解压，例如：

```bash
cd /www/wwwroot
unzip lab_equipment_backend_deploy.zip
cd lab_equipment_backend
```

2. 执行一键部署脚本：

```bash
bash deploy/install.sh
```

脚本会依次完成：

- 创建 `venv` 并安装 `requirements.txt`
- 交互式生成 `.env`（数据库地址、账号、密码、SECRET_KEY、ALLOWED_HOSTS）
- 自动创建数据库 `lab_equipment`（不存在时）
- 执行 `python manage.py migrate` 建表
- 执行 `python manage.py seed_admin` 创建管理员
- 注册并启动 systemd 服务 `lab-equipment`（Gunicorn 监听 `127.0.0.1:8000`）

3. 默认管理员：

```
学号/工号：ADMIN001
密码：admin123
```

## 四、手动部署（不使用 install.sh）

```bash
cd /www/wwwroot/lab_equipment_backend
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
vi .env          # 填写 DB_HOST/DB_USER/DB_PASSWORD 等
python manage.py migrate
python manage.py seed_admin

# 前台启动（调试）
bash deploy/start.sh

# 或后台启动
nohup bash deploy/start.sh > gunicorn.log 2>&1 &
```

## 五、验证

```bash
# 健康检查（应返回 code=200 和 token）

  -H 'Content-Type: application/json' \
  -d '{"userNo":"ADMIN001","password":"admin123"}'

  -H 'Content-Type: application/json' \
  -d '{"userNo":"ADMIN001","password":"admin123"}'
```

浏览器打开 `http://62.234.128.72:6664`，使用 `ADMIN001 / admin123` 登录。

## 六、常用运维命令

```bash
systemctl status lab-equipment     # 查看状态
systemctl restart lab-equipment    # 重启（更新代码后）
systemctl stop lab-equipment       # 停止
journalctl -u lab-equipment -f     # 实时日志
```

更新代码后：

```bash
cd /www/wwwroot/lab_equipment_backend
# 覆盖代码后
source venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
systemctl restart lab-equipment
```

## 七、常见问题

| 现象 | 排查 |
|------|------|
| 前端接口 502 | 后端未启动：`systemctl status lab-equipment`、`journalctl -u lab-equipment -n 50` |
| 接口返回 404 | 确认 Nginx 的 `/real-api/` 转发到 `http://127.0.0.1:8000/`，后端路径为 `/api/v1/...` |
| 数据库连接失败 | 检查 `.env` 中 `DB_HOST/DB_PORT/DB_USER/DB_PASSWORD/DB_NAME` |
| 表不存在 | 执行 `python manage.py migrate` |
| 登录提示用户名或密码错误 | 执行 `python manage.py seed_admin` 重置管理员密码 |
| 图片上传后无法显示 | 按 `deploy/nginx-media.conf` 在站点配置中增加 `/media/` 目录，执行 `nginx -t && nginx -s reload` |

## 八、说明

- 数据库结构以 Django migrations 为准，`sql/schema.sql` 仅作结构参考；**不要**在导入 schema.sql 后又执行 migrate，二者会冲突。
- 生产环境 `.env` 中 `DEBUG=False`，请勿改回 True。
- `SECRET_KEY` 由 install.sh 自动生成随机值，请勿泄露。
